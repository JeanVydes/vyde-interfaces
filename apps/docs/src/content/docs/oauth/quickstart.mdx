This guide takes a user from your login button to an authenticated Vyde API request. The examples
use one flow; select the language you are using in each step.

## How the flow works

<div class="mermaid">
sequenceDiagram
    participant App as Your application
    participant Browser
    participant Vyde as Vyde Identity
    participant API as Vyde API
    App->>App: Generate state and PKCE verifier
    App->>Browser: Redirect to authorization
    Browser->>Vyde: Login and consent
    Vyde-->>Browser: Redirect with code and state
    Browser->>App: Callback
    App->>App: Verify state
    App->>Vyde: POST token
    Vyde-->>App: Access and refresh tokens
    App->>API: Bearer access token
    API-->>App: Delegated response
</div>

## Before you start

1. Create an application in the [Identity Console](https://identity.vyde.dev/organizations).
2. Choose **Public** for a browser, mobile, desktop, or CLI app. Choose **Confidential** for a
   server-side app.
3. Register the exact callback URL used by your application.
4. Enable `authorization_code`, `refresh_token`, and only the scopes you need.

<details class="developer-details">
<summary>Developer settings: endpoints and local environments</summary>

Production authorization endpoint: `https://identity.vyde.dev/oauth2/authorize`.

Production token and API base: `https://api.vyde.dev`.

Use `/.well-known/openid-configuration` instead of hardcoding endpoint paths in a reusable
integration. Local development uses the `.test` hosts configured by your project.

</details>

## 1. Start the authorization request

Generate both values for every login attempt. Store `state` and `verifier` in the user's
server-side login transaction; do not put the verifier in a URL or browser storage.

Redirect the user's browser to `authorizationUrl`. Vyde authenticates the user and displays
consent when required.

## 2. Handle the callback

Vyde redirects to the registered URI:

```text
https://app.example.com/oauth/callback?code=ONE_TIME_CODE&state=GENERATED_STATE
```

Compare the returned `state` with the server-side value before doing anything else. If it differs,
discard the callback and do not exchange the code. On denial, handle `error`, `error_description`,
and `state` without attempting a token exchange.

## 3. Exchange the code

The request is form-encoded. Public clients omit `client_secret`; confidential clients send it only
from their backend.

  method: 'POST',
  headers: { 'content-type': 'application/x-www-form-urlencoded' },

    grant_type: 'authorization_code', code, client_id: clientId,

## 4. Call the API

Use the access token as a bearer token. Never send a refresh token to an API resource.

```bash
curl https://api.vyde.dev/v1/accounts/me \
  -H 'authorization: Bearer ACCESS_TOKEN'
```

The response contains the requested resource. See the [API reference](/oauth/api) for request
bodies, response shapes, and error handling.
